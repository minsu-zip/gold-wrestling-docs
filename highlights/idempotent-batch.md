# 상태 기반 멱등 배치

횟수권을 2주 동안 쓰지 않으면 1회를 차감합니다. 배치는 매일 새벽에 돌고, 같은 날 두 번 돌아도, 며칠 멈췄다 돌아도 결과가 같아야 합니다.

## 문제

- "오늘 이미 실행했나"를 실행 이력으로 가드하면 캐치업이 안 됩니다. 이력이 유실되면 이중 차감됩니다.
- 이용권마다 "다음 차감 예정일" 컬럼을 두면 원장과 별도의 상태가 생깁니다.
- 기준일을 마지막 출석일로만 잡으면 출석 체크를 빠뜨린 회원이 부당 차감됩니다. 배포 전 과거 전체가 부채로 잡히는 문제도 있었습니다.

## 결정

배치는 실행 횟수가 아니라 상태를 봅니다 (D-106).

> 있어야 할 차감 수 = ⌊기준일부터 오늘까지 경과일 / 14⌋
>
> 부족분 = 있어야 할 차감 수 − 기준일 이후 실제 INACTIVITY 이력 수

부족분만 차감합니다. 중복 실행은 부족분이 0이라 아무것도 하지 않고, 밀린 실행은 몰아서 차감합니다. 멱등성과 캐치업이 한 메커니즘입니다.

기준일은 다섯 후보의 최근값입니다 (D-105, D-147). 마지막 출석일, 취소되지 않은 마지막 예약의 수업일, 휴회·비활성에서 벗어난 시각, 횟수권 등록일, 마지막 충전일. "차감 제외 기간에는 부채가 쌓이지 않는다"는 원리의 구현입니다.

| 안전장치 | 기본값 | 막는 것 |
| --- | --- | --- |
| 정책 시행일 하한 | 2026-09-01 | 배치가 없던 과거 전체가 부채로 계산되는 것 (D-119) |
| 실행 1회당 회원별 최대 차감 | 1 | 사고가 나도 하루 1회씩만 누적 |
| 자동 실행 킬 스위치 | 꺼짐 | 설정을 빠뜨리면 "돌지 않는" 쪽으로 실패 (D-121, D-151) |

자동 실행을 기본 꺼짐으로 둔 이유는 실패 비용이 비대칭이기 때문입니다. 잊어서 안 도는 것은 아무 일도 일어나지 않지만, 잊어서 도는 것은 회원 횟수가 사라집니다. 운영에서는 출석 배선 확인 → 수동 실행 1회 검증 → 환경변수 명시의 3단계로 켭니다. 저녁반 0.5회 차감은 자동화하지 않고 출석 체크 시 관리자가 처리합니다 (D-127).

## 검증

- 부족분 계산과 기준일 선택은 단위 테스트로 경계값(13일, 14일, 28일, 시행일 이전)을 고정했습니다.
- 같은 날 두 번 실행, 3일 뒤 실행, 수동 실행 직후 자동 실행이 같은 결과를 내는지 통합 테스트로 확인했습니다.
- 동시 실행은 DB 부분 유니크로 거부되고 409로 응답합니다 (D-117, D-118).
