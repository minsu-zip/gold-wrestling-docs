# 상태 기반 멱등 배치

횟수권을 2주 동안 쓰지 않으면 1회를 차감한다. 배치는 매일 새벽에 돈다. 같은 날 두 번 돌아도, 며칠 멈췄다 돌아도 결과가 같아야 한다.

## 문제

- "오늘 이미 실행했나"를 실행 이력으로 가드하면 캐치업이 안 된다. 배치가 3일 멈추면 밀린 주기가 사라지거나, 이력이 유실되면 이중 차감된다.
- 이용권마다 "다음 차감 예정일" 컬럼을 두면 원장과 별도의 상태가 생긴다. 진실 원천이 둘이 된다.
- 기준일을 마지막 출석일로만 잡으면 관리자가 출석 체크를 빠뜨린 회원이 부당 차감된다. 배포 전 과거 전체가 차감 부채로 잡히는 문제도 있다.

## 결정

**배치는 실행 횟수가 아니라 상태를 본다** (D-106). 회원별로

> 있어야 할 차감 수 = floor(기준일부터 오늘까지 경과일 / 14)
> 부족분 = 있어야 할 차감 수 − 기준일 이후 실제 `INACTIVITY` 이력 수

부족분만 차감한다. 중복 실행은 부족분이 0이라 아무것도 안 하고, 밀린 실행은 부족분이 커져 몰아서 차감한다. 멱등성과 캐치업이 한 메커니즘이다.

기준일은 다섯 후보의 max다 (D-027 → D-105 → D-147). 마지막 출석일, 취소되지 않은 마지막 예약의 수업일, 차감 제외 상태(휴회·비활성)에서 벗어난 시각, 횟수권 등록일, 마지막 양(+) 수동 가감일. "차감 제외 기간에는 부채가 쌓이지 않는다"는 원리의 구현이다.

안전장치 세 개를 설정값으로 뒀다 (D-119, D-121).

| 설정 | 기본값 | 막는 것 |
| --- | --- | --- |
| 정책 시행일 하한 | 2026-09-01 | 배치가 없던 과거 전체가 부채로 계산되는 것 |
| 실행 1회당 회원별 최대 차감 | 1 | 사고가 나도 하루 1회씩만 누적. 관리자가 멈출 시간이 생긴다 |
| cron 킬 스위치 | 꺼짐 | 설정을 빠뜨리면 "돌지 않는" 쪽으로 실패한다 |

실행 직렬화는 `batch_execution` 테이블의 `RUNNING` 행에 부분 유니크 인덱스를 걸어 DB가 보장한다 (D-117). 두 번째 실행은 INSERT가 거부되고 409로 응답한다. 시작 기록이 먼저 남으므로 전체 실패 시에도 이력이 한 줄은 남는다. 트랜잭션 경계는 회원 1명 = 트랜잭션 1개다 (D-112).

## 검증

- 부족분 계산과 기준일 max는 단위 테스트로 경계값(정확히 14일, 13일, 28일, 시행일 이전)을 고정했다.
- 같은 날 두 번 실행, 3일 뒤 실행, 수동 실행 API 직후 cron 실행이 같은 결과를 내는지 통합 테스트로 확인했다.
- `RUNNING` 부분 유니크는 Flyway V10 마이그레이션이고, 동시 실행 거부는 409 `BATCH_ALREADY_RUNNING`으로 [에러 코드](/tech/error-codes)에 계약으로 올라 있다 (D-118).
- 운영 활성화는 3단계 절차(출석 배선 확인 → 수동 실행 1회 → 킬 스위치 켜기)로 BE README에 있고, 실행은 BE Phase 10에서 한다.
